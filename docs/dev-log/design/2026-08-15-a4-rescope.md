# A4 design pass — three of the four clusters are not what the arc list assumed

Date: 2026-08-15 · lane: DRM.jl catch-up · the design pass A4a–A4d required
before starting · anchor drmTMB **0.7.0**

The A3c pass paid for itself by finding a dependency and an uncertainty trap
before any code was written. This one pays for itself harder: **three of the four
A4 clusters are misscoped**, and implementing them as listed would have produced
work that either duplicates R, belongs behind a parked fence, or does not exist.

## OWNER DECISIONS — 2026-08-15, both confirmed

- **A4a → #49 PARKED.** `categorical` is an imputation family; it moves to the
  missing-data cluster and is **not** built as a response family.
- **A4b → deliberately-not-ported.** `make_mesh` / `spatial_coords` are R-side
  geospatial preparation and are recorded as such, not as open capability gaps.

Both are now settled; the tables below are the reasoning that led there.

## Cluster-by-cluster verdict

| arc | as listed | what it actually is | verdict |
|---|---|---|---|
| **A4a** | "`categorical` family" | **Not a response family.** `categorical()` returns a `drm_impute_family` (`R/missing-data.R`), link `baseline_softmax` — an **imputation** family | **MOVE to the #49 missing-data cluster, which is PARKED.** Not an A4 item |
| **A4b** | spatial mesh: `make_mesh`, `spatial_coords` | R-side **geospatial data prep** (`R/mesh.R`): validates a projected CRS via `sf::st_crs`, rejects lon/lat, converts coordinates | **Propose OUT OF SCOPE** — see below |
| **A4c** | phylo penalty | `drm_phylo_penalty(sd_u, sd_alpha, cor_sd)` (`R/penalty.R`) — a PC-prior-style penalty spec that **changes the objective** | **GENUINE engine capability.** Keep |
| **A4d** | misc accessors | mixed; see the table below | **Split** |

## A4b — why spatial mesh is proposed out of scope

`make_mesh` takes a data frame of lon/lat, validates that `crs_out` is a
*projected* CRS through `sf`, refuses a longlat CRS, and returns projected
coordinates. It runs **before** any model is fitted, and its dependency is the R
geospatial stack.

An R user calling `drmTMB(..., engine = "julia")` prepares coordinates in R and
passes the projected values through. Porting it would mean taking a Julia
CRS/projection dependency to duplicate a step that already happens on the R side
and never reaches the engine.

This is the same shape as the A2a finding — `qq_plot`/`worm_plot` and friends
needed a payload, not Julia ports, because they run R-side on the returned
object. **Not every drmTMB export needs a Julia twin.** The ledger counts
export-name gaps; it does not decide which gaps are capability.

Recommend recording `make_mesh` / `spatial_coords` in the ledger as
**deliberately-not-ported, R-side data preparation**, with that reason attached,
rather than leaving them as open gaps that imply missing capability.

## A4d — split by what each thing actually is

| export | in DRM.jl? | what it is | action |
|---|---|---|---|
| `rho_latent` | **present** | bridge accessor | nothing to do |
| `corpair` | absent | **formula MARKER** (`invisible(NULL)`, intercepted at parse) taking `group, level, block, class, from, to` | **grammar parity item.** `AGENTS.md` Boole contract already names `corpair(level=/block=/from=/to=)`. Touching `bf()` ⇒ **`DRM_PARITY_TESTS=1` is mandatory** |
| `structured_effects` | absent | accessor in `methods.R` | assess: likely a post-fit summary ⇒ may be a payload item, not an engine port |
| `profile_targets` | absent | `R/profile.R` — enumerates profile-able targets | assess against DRM.jl's existing `profile_result` / `profile_curve` |
| `meta_vcov_bivariate` | absent | `R/meta-vcov.R` — bivariate meta known-V construction | genuine, but sits next to the meta route whose `V_known` was just handled |

Note DRM.jl already exports `corpairs` (plural, the post-fit accessor). `corpair`
(singular) is the *marker*. They are different objects and the near-identical
names are a trap for anyone reading the gap list quickly.

## What this changes about the countdown

The ledger's 22 export gaps include at least four that are **not capability
gaps**: `categorical` (parked cluster), `make_mesh`, `spatial_coords` (R-side
prep), and arguably the distributional-outputs five already resolved by payload.
A gap count that mixes "missing capability" with "correctly lives in R" overstates
the work. Recommend `tools/parity_ledger.py` grow a
`deliberately-not-ported` classification so the countdown measures what it claims.
