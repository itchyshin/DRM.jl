# A4d design pass — `corpair` marker, and which of the three accessors to build

Date: 2026-08-15 · lane: DRM.jl (Claude, arc-loop) · anchor: drmTMB **0.7.0** @ `origin/main`

The A4 re-scope re-scoped three of four clusters before a line was written. This
pass does the same for what remains, and reaches the same kind of answer: **one
of the three A4d-2 exports should not be built at all**, and A4d-1 is a
*grammar* slice, not a fitting slice.

## A4d-1 — `corpair`

### What it is

`drmTMB::corpair(group, level = NULL, block = NULL, class = NULL, from = NULL, to = NULL)`
(`R/formula-markers.R:388`) is `invisible(NULL)` — a pure marker that exists only
to be parsed out of a formula. It is **not** `corpairs()`, the post-fit accessor
DRM.jl already exports (`src/gaussian_core.jl:1037`). Conflating the two off a
gap list is the easy mistake; drmTMB's own roxygen calls out the distinction.

### The structural difference that sets the scope

Every structured marker DRM.jl already has — `phylo()`, `relmat()`, `animal()`,
`spatial()`, `meta_V()` — appears on the **right** of a formula and is
intercepted by `_split_ranef` (`src/gaussian_ranef.jl:13`). `corpair` appears on
the **left**:

```r
corpair(id, level = "phylogenetic", block = "p", from = "mu1", to = "mu2") ~ x
```

DRM.jl's `bf()` requires each secondary formula's LHS to be a bare `Term`
(`src/gaussian_core.jl:101`), so such a formula dies today with
*"each distributional-parameter formula must read `param ~ …`"*. Supporting
`corpair` therefore means teaching `bf()` about a `FunctionTerm` LHS — a real
front-end change, which is why this arc carries the mandatory
`DRM_PARITY_TESTS=1` rail.

### Why this is parse-and-reject, not parse-and-fit

In drmTMB, a parsed `corpair` goes down one of two paths:

- **univariate / non-bivariate** → hard rejection (`R/drmTMB.R:2946`):
  *"`corpair()` formula syntax is reserved but not implemented yet."*
- **bivariate Gaussian, `level = "phylogenetic"`** → a real engine path that
  attaches a group-level design to a **labelled bivariate covariance block**.

That second path needs `block = "p"` to name a labelled covariance block — the
`(1 | p | id)` grammar. **DRM.jl has no labelled covariance-block grammar at
all**: `_split_ranef` reads only `t.args[1]` and `t.args[2]` of a `|` term. So
drmTMB's fitted `corpair` route has no counterpart here, and building one is a
covariance-block-grammar slice, not a marker slice.

**Scope, therefore:** full marker + full LHS parse + all of drmTMB's validation,
then refuse at fit with drmTMB's own reserved-not-implemented message. That is
not a shortcut — it is exactly what drmTMB itself does for every non-bivariate
model, so an R user pasting a `corpair` formula into DRM.jl gets the *same*
error they would get from the twin on the same model class.

Deliberately **not** claimed: that DRM.jl can fit a `corpair` model.

### The 12 rejections to mirror

From `parse_corpair_lhs` (`R/parse-formula.R:375-482`) and
`parse_corpair_string_arg` (`:485`): named corpair formula; not exactly one
grouping variable; group not a symbol; unknown option; repeated option;
non-string option; bad `level` (allowed `group` / `phylogenetic` / `spatial`);
bad `class` (allowed `location-location` / `location-scale` / `scale-scale`);
`from`/`to` supplied singly; `class` together with `from`/`to`; bad endpoint
(allowed `mu1` / `mu2` / `sigma1` / `sigma2`); `from == to`.

`test/test_bf_grammar.jl`'s house convention applies: every rejection gets a
`@test_throws ArgumentError` *and* an `occursin` assertion that the message
points at the right alternative.

### Also in scope

`docs/src/rosetta.md:117` currently maps `corpair(fit)` → `corpairs(fit)`, which
implies `corpair` is an accessor. It is a marker. That line is wrong today,
independently of this arc.

## A4d-2 — build two, refuse one

| export | what it really is | verdict |
|---|---|---|
| `profile_targets` | Post-fit **inventory** (`R/profile.R:660`): enumerates every name `confint(..., method = "profile")` accepts, with a readiness column. Runs no optimisation. | **BUILD** — thin public wrapper over the existing private `_profile_jobs` (`src/inference.jl:250`) plus readiness, which `profile_result`'s dispatch already computes implicitly. Cheap, real user value. |
| `structured_effects` | Post-fit **metadata reshaper** (`R/methods.R:233`): one row per structured marker so downstream tools "do not need to grep or re-parse formula text". No engine effect. | **BUILD** — reconstructible from `_collect_structured(fit.formula)` (`src/gaussian_ranef.jl:46`); `DrmFit` already retains the formula. |
| `meta_vcov_bivariate` | **Input constructor** (`R/meta-vcov.R:40`): builds the dense `2n × 2n` known sampling-covariance `V` for bivariate meta-analysis. | **DO NOT BUILD — blocked.** |

### Why `meta_vcov_bivariate` is refused

DRM.jl's `meta_V` is **diagonal-only**. `src/gaussian_meta.jl:16` says so
outright ("dense/bivariate sampling covariance is planned"); `meta_V(v)` marks a
single data *column*, read as `vv = Float64.(getproperty(data, metav))`
(`src/gaussian_core.jl:566`) and consumed as a scalar per row,
`var = vv[i] + exp(2·ησ[i])` (`src/gaussian_meta.jl:28`). The bivariate Gaussian
route does not consume `metav` at all.

So porting `meta_vcov_bivariate` would ship an exported function whose output
**nothing in DRM.jl can accept** — an export-name gap closed without closing a
capability gap, which is precisely the measurement error A4e exists to fix. It
would make the ledger look better while making the package no more capable.

Recorded instead as a written `claim_boundary`: blocked on a dense bivariate
`V_known` engine path. That keeps GOAL.md's closure rule satisfied — every row is
either `supported` with a fixture, or carries an explicit reason why not.
