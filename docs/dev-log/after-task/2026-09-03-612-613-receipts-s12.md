## 3a. Decisions and Rejected Alternatives

- **#612 regenerated receipts with no tolerance changes** — the failing
  ordinal/categorical cells (4e-6 bar) were left failing and measured
  honestly rather than loosening the bar to make them pass; the owner call on
  non-Gaussian tolerance is deferred to #606, not decided inside an
  evidence-only PR.
- **#613 built matched R/Julia timing tools with the same interface and
  column names** rather than ad hoc per-language scripts — makes the compare
  step (`warm_timing_compare.jl`) a straightforward join rather than a
  bespoke reconciliation per workflow.
- **#613 used loop-until-0.25s timers** rather than a single timed call,
  specifically because R's `proc.time()` is millisecond-floored and would
  under-resolve the faster legs — a single call could misreport a fast leg as
  0ms.
- **#613 verified the uncertainty-leg computation against the cached/stored
  value on both sides** (Julia: fresh Hessian vs cached `vcov`; R: fresh
  `sdreport()` vs `fit$sdr$cov.fixed`) rather than trusting the forced
  recomputation was equivalent — this is what makes the uncertainty leg's
  timing comparable to the cached value elsewhere in the codebase.
- **#613 followed the D-139 estimate-before-you-run protocol**: a smoke test,
  then a single p=2048 pre-run pilot (R 7.1s / Julia 0.4s, identical loglik)
  to validate correctness and get a time estimate, before committing to the
  full 9-minute sweep — catches a wrong answer, not just a slow one.

## 6. Tests of the Tests

- **#612** is itself a re-verification exercise: re-running the ledger's own
  generators against current `src` is precisely how a stale-receipt defect
  (numbers frozen to an old build) would be caught — and the PR body reports
  it *did* catch three receipts that needed regenerating, plus confirms the
  ordinal/categorical failures are real (measured, not an artifact of a stale
  baseline).
- **#613's** pre-run pilot at p=2048 (identical loglik between R and Julia)
  is the correctness check that must pass before the timing numbers from the
  full sweep can be trusted — a timing harness that silently fit different
  models on each side would produce a meaningless "win" regardless of the
  wall-clock numbers.

  running every call, not by inspection) is direct evidence the harness
  exercises the real R call path rather than a simplified stand-in.

## 11. Team Learning

- **A receipt is only as current as its last regeneration** — #612's finding
  (three receipts needed regenerating even absent code changes to the closed
  gates) is a reusable reminder to periodically re-run ledger generators
  against current `src`, not just at the moment a gate is first closed.
- **Building a formula-grammar-exercising harness catches grammar mistakes a
  written-from-memory registry would not** — #613's four caught R mistakes
  came from actually running every call, which generalises to any future
  cross-language registry: write it, then execute every row before trusting
  it, don't just transcribe the grammar from documentation or memory.
- **Verify a timing harness's uncertainty leg against a known-good cached
  value on both sides before trusting its wall-clock number** — otherwise a
  "fast" uncertainty leg could just mean it silently skipped the expensive
  part.
