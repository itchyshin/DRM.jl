  symmetric covariance, PD on the fixed-effect block, agreeing with an
  independent double-central-difference Hessian of the fit's own marginal NLL
  to `< 1e-5` relative.
- `_vcov_from_hessian` never returns NaN (pinv fallback + warning) and is
  confirmed not on this path.
- `test/test_q4_reml_vcov.jl` (new, 12/12, wired mid-file): native finite/PD +

  explicitly set.

## 3a. Decisions and Rejected Alternatives

- **#611: document the default rather than change it.** The NaN vcov is
  deliberate (`_bridge_fit`'s `q4_vcov = false` default for bridge bivariate
  q=4 phylo fits) — rejected silently "fixing" it by flipping the default in
  this PR; the PR explicitly frames the default-flip question as an **owner
  decision**, not something to resolve unilaterally in a test-only slice.
  `[se]` provenance was added as `not_comparable` rather than omitted, so the
  receipt is on record even though it cannot be compared under the current
  default.
- **#607: independent reimplementation of the masked lift, not a
  re-assertion of the existing code's output.** The test builds its own
  `leaf_hess`-based masked-lift calculation from the same per-row masks,
  rather than snapshotting `_reml_border_blocks`'s current output — this is
  what makes the `atol = 1e-12` check non-tautological (confirmed by checking
  it against the pre-#575 *unmasked* call, which does NOT reproduce the
  output).
- **#607: q=2 structured bivariate route's outright refusal of missing
  responses is out of scope**, flagged rather than silently worked around —
  the end-to-end check therefore runs through the q4 engine only.

## 11. Team Learning

- **A NaN result is not automatically a bug** — #611's main lesson is that
  tracing a suspicious numerical output (all-NaN vcov) back to a *deliberately
  documented default* (rather than assuming a defect and patching around it)
  is the correct first move, and the test-only PR that pins this as expected
  behaviour is more valuable than a premature "fix."
- **Non-tautological masked-lift testing pattern (#607):** building an
  independent reimplementation of a masking calculation from the same raw
  inputs (rather than snapshotting the existing function's output) and then
  confirming the *pre-fix* code does NOT reproduce it, is a reusable template
  for "this closes a coverage gap, not a bug" PRs — it proves the test can
  discriminate correct from incorrect masking, not just that the current code
  is self-consistent.
