## Where the plan was wrong, and how

**A4d-1 was planned as buildable and is not.** The design pass assumed the syntax
could be expressed in Julia. It cannot: StatsModels' `@formula` rejects both
keyword arguments and string literals at macro-expansion, before any DRM.jl code
runs. That was discovered by *testing the macro*, not by reading about it — the
plan would have survived another round of code-reading intact.

Per the loop's own rule ("a genuine surprise that invalidates the plan is a STOP,
not an improvisation") this was **not patched around**. No divergent marker was
built. It is recorded as blocked with two independent reasons.

**A4e forced a correction to a claim I had already made.** Earlier in the run I
reported that 9 of the 22 ledger gaps were "already implemented in `src/` under
other export names". Right in count, **wrong in reason** — the evidence was a
text grep that matched string literals and comments, not definitions. None of the
nine is a Julia symbol.

This is exactly the invariant `GOAL.md` names: *"a narrow or negative search is
not proof."* I violated it, stated a conclusion from it, and the correction is
recorded in the A4e commit, its check-log entry, and its PR body rather than
quietly fixed.

## Verification NOT skipped, and one that was caught

Every arc ran the full local suite before pushing. Two failures were caught this
way and are worth recording because both were mine:

1. A docstring containing `tree$edge.length` — `$` interpolates in Julia
   docstrings, so the package stopped precompiling. Caught by the full suite,
   **not** by the targeted tests I had run just before.
2. Adding `penalized_map` broke `test_check_drm.jl`'s key-tuple contract test.
   That test then caught a *second* field addition (`vcov_complete`) later in the
   same stack. It is doing its job.
