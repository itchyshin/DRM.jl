# 2026-08-24 — The SE axis: making interval reliability measurable

**Lane:** Hopper (R↔Julia parity), branch `parity/se-axis`.
**Scope fence (restated, binding):** SE *agreement* between two engines is NOT
interval *coverage*. Nothing in this slice makes, implies, or enables a
coverage claim. Both `interval_status != "coverage_claimed"` assertions
(`test/test_parity_biv_q4_phylo_reml.jl:72`,
`test/test_parity_gaussian_phylo_mean.jl:77`) are untouched.

## What was built

1. **`test/parity/compare.jl`** — a per-coefficient standard-error comparator:
   - `ParityExpected` gains `se::Dict{String,Float64}` (empty default) and
     `se_not_comparable::Vector{String}` (empty default). Keyword constructor
     defaults keep every existing caller — `loadfixture.jl`,
     `test_parity_harness.jl` — working unchanged.
   - `drm_se_named(fit)` — flattens `sqrt.(diag(vcov(fit)))` to the fixture's
     `"<param>_<coefname>"` names, using the same block walk as
     `drm_coef_named`.
   - `compare_se(fit, expected)` / `compare_se(se::AbstractDict, expected)` —
     the entry point (`isdefined(Main, :compare_se)` is true after
     `include("test/parity/compare.jl")`). Returns
     `(passed, failures, skipped)`; never throws on a mismatch.
   - Wiring: `compare_fit` (check 7) and `compare_bridge` run the SE check
     automatically when a fixture supplies `[se]`; fixtures without `[se]`
     skip the axis entirely (backward compatible — see verification below).
2. **`tools/parity_se.R`** — Route-2 live-R script (same `cells` shape and
   TSV contract as `tools/parity_fixture.R`): fits the SAME target through
   `drmTMB(engine = "tmb")` and `drmTMB(engine = "julia")` and compares
   per-coefficient SEs. Includes a mandatory in-script negative control.
3. **`docs/dev-log/evidence/parity-se.tsv`** — the measured evidence.

## Schema decision and rationale

```toml
[se]                                  # OPTIONAL — absent block ⇒ axis unmeasured
"mu_(Intercept)" = 0.070945           # flat keys, exactly like [coef]
"sigma_x"        = 0.052300
not_comparable   = ["sd_phylo_(Intercept)"]   # reserved key, optional

[tol]                                 # per-case overrides, existing pattern
rtol_se = 1e-3
atol_se = 1e-8
```

- **Flat `[coef]`-style keys**, because downstream fixture generators already
  emit that shape for `[coef]` — one more block, same naming pipeline, and the
  comparison is order-independent by construction. The alternative (deriving
  SEs from the existing `[vcov]` block) was rejected: almost no fixture
  carries a full `vcov`, a full matrix is a much heavier regeneration burden
  than a diagonal, and vcov off-diagonals fail for reasons that have nothing
  to do with the SE axis.
- **Reserved `not_comparable` key** (see Boundary discipline below): a flat
  array of names whose SEs must be recorded-but-not-compared. A coefficient
  name can never collide with the bare key `not_comparable`, so the block
  stays a single flat table.
- Tolerances ride the existing `[tol]` override mechanism (`rtol_se`,
  `atol_se`) rather than a new block.

## Tolerance rationale (defaults: `rtol_se = 1e-3`, `atol_se = 1e-8`)

SEs are second-order quantities — square roots of the diagonal of an inverse
observed information — and will never agree at the `1e-4` coefficient
tolerance. Three anchors set the default:

1. **Consistency:** `rtol_vcov = 1e-3` is the harness's existing second-order
   tolerance; SE = sqrt(variance) inherits roughly *half* the relative error
   of the vcov diagonal, so `rtol_se = 1e-3` is the same-order,
   slightly-conservative choice.
2. **Measured headroom:** the 2026-08-24 run measured max relative SE
   disagreement of **2.2e-6** across all three cells (table below) — the
   default is ~500× looser than reality, so it will not produce flaky reds on
   harder cells where finite-difference Hessians get noisier.
3. **Still diagnostic:** a genuine information-matrix discrepancy (e.g. one
   engine switching to *expected* information, a wrong df correction, a
   Hessian at the wrong point) moves SEs at the percent level or more —
   `1e-3` rejects all of those. The +10% negative control fails by two orders
   of magnitude.

`atol_se = 1e-8` only matters for SEs near zero, which the boundary
discipline treats separately.

## Information-matrix finding

Both engines compute **observed**-information Wald SEs — no
observed-vs-expected mismatch exists on the covered cells:

- drmTMB: TMB `sdreport` covariance (`R/methods.R` `vcov.drmTMB`, via
  `sdr$cov.fixed` / `sdr$cov`), i.e. inverse Hessian of the (Laplace)
  objective at θ̂.
- DRM.jl: `src/locscale_infer.jl` `_ls_obs_information` — symmetric central
  finite-difference Jacobian (h = 1e-5) of the *exact* marginal gradient at
  θ̂, inverted in `_ls_vcov`.

The measured ~1e-6 relative agreement (including the Laplace random-effect
cell) is consistent with two observed-information constructions differing
only in differentiation scheme and optimizer endpoint. Caveat: this is
established **for the covered cells only**; families with dedicated inference
paths (q4 phylo REML, experimental variants) are not yet measured on this
axis.

## Boundary discipline (from the W2-D sibling finding)

W2-D established that DRM.jl bounds log-SDs at
`_LAPLACE_LOG_SD_FLOOR = log(1e-6)` (`src/sparse_laplace_glmm.jl:149`) while
drmTMB `origin/main` has no equivalent floor on a phylogenetic variance
component — so on near-degenerate draws the two engines converge to
*different kinds of points* (DRM.jl pinned ON its floor, drmTMB interior). An
SE evaluated at a constrained boundary optimum is not the same quantity as an
interior-optimum SE, and **no tolerance choice can absorb that** — a naive
comparator would emit either a spurious FAIL or, worse, a spurious PASS.

Built into the design, not left to be discovered:

1. **Schema:** the `[se]` block's reserved `not_comparable` array records,
   per parameter, that the reference fit was boundary-pinned and comparison
   is declined. The raw (degenerate) SE value may still be recorded alongside
   for reference; `not_comparable` wins.
2. **Comparator:** `compare_se` never numerically compares such names, and
   also accepts a `boundary = [...]` keyword for DRM.jl-side detection
   (boundary detection is family-specific θ-level work — probing against
   `DRM._LAPLACE_LOG_SD_FLOOR` — so the caller who owns the fit supplies the
   names). All declined names are returned in a third `skipped` field with
   their reason: *"compared and agreed"* and *"declined to compare"* stay
   distinguishable downstream. A non-finite SE that was NOT declared is a
   FAILURE whose message points at `not_comparable` — silence is impossible
   in either direction.
3. **R script:** `tools/parity_se.R` guards with a heuristic proxy (any
   non-finite or ≤ 1e-6 SE on either side ⇒ status `BOUNDARY_NOT_COMPARABLE`,
   never PASS/FAIL) and its cells were **chosen with variance components well
   away from any floor** — the random-intercept cell uses a true group SD of
   0.5 with 30 groups × 8 obs (fitted SEs ≈ 0.04–0.11, nowhere near 1e-6).
   This choice is deliberate and stated here rather than made quietly.

## Measured SE agreement (docs/dev-log/evidence/parity-se.tsv, 2026-08-24)

Environment: R 4.6.0, drmTMB 0.7.0, Julia 1.10.0, JuliaCall; same-target
fits through `drmTMB(engine = "tmb")` vs `drmTMB(engine = "julia")`.

| cell_id | target | k | max abs Δse | max rel Δse | status |
|---|---|---|---|---|---|
| se_gaussian_location_scale | `bf(y ~ x, sigma ~ z)`, gaussian | 4 | 1.499e-07 | 2.169e-06 | SE_PASS |
| se_biv_gaussian_rho12 | `bf(mu1=y1~x, mu2=y2~x, sigma1~1, sigma2~1, rho12~1)`, biv_gaussian | 7 | 9.176e-08 | 1.835e-06 | SE_PASS |
| se_gaussian_group_ranef | `bf(y ~ x + (1|g), sigma ~ 1)`, gaussian (Laplace) | 3 | 5.419e-08 | 4.979e-07 | SE_PASS |

All matching is now **by name** after normalising the engines' label
separators (finding: native drmTMB labels `mu:(Intercept)` with a colon, the
julia engine `mu_(Intercept)` with an underscore — the reason
`tools/parity_fixture.R`'s coef comparison silently falls back to positional
matching; `parity_se.R` normalises `:` → `_` and matches exactly).
