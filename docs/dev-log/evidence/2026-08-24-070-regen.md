## A finding, not a drift: hand-added `[tol]` overrides get wiped by regeneration

Three fixtures (`meta-analysis-V`, `nbinom2-dispersion`, `robust-student`) had
extra, hand-added `[tol]` lines in their committed `expected.toml` — tolerance
widenings (`atol_vcov`, `atol_coef`) with explanatory comments documenting
small DRM.jl-vs-drmTMB "soft optimizer" deltas from prior work (#392, #370).
`write_expected()` in `gen_fixtures.R` only ever emits `atol_loglik` /
`atol_aic` (plus `atol_ranef`/`rtol_ranef` when a `[ranef]` block is present)
— it has **no knowledge of these three manually-added overrides**, so a plain
regeneration silently drops them.

Since the numeric `[coef]`/`[vcov]` content for these three fixtures came back
byte-identical to what was there before, the override values were still
correct and were restored by hand (not regenerated) onto the freshly-written
files:

- `meta-analysis-V`: `atol_vcov = 3e-8`
- `nbinom2-dispersion`: `atol_coef = 2e-5`
- `robust-student`: `atol_coef = 2e-5`, `atol_vcov = 3e-8`

**This is a real gap in `gen_fixtures.R`**, worth fixing properly at some
point (e.g. read-back-and-preserve any existing `[tol]` overrides, or move
them into a small sidecar the generator doesn't own) so a future regeneration
doesn't need a human to notice and hand-restore them. Not fixed here per the
task's scope (asked to flag loudly if `gen_fixtures.R` needs repair, not to
redesign its tolerance-preservation story) — flagging it here.

## `[se]` block — added

`compare.jl` / `loadfixture.jl` already support an optional `[se]` block
(flat `"<param>_<coefname>"` keys, same convention as `[coef]`, plus a
reserved `not_comparable` array) and treat its absence as "SE checks
skipped." Since every fixture already carries a full `[vcov]` matrix, the
per-coefficient Wald SE is simply `sqrt(diag(V))` in the same `order` — no
extra R call, no contortion. Added a ~10-line block to `write_expected()` in
`gen_fixtures.R` (right after `[coef]`, before `[vcov]`) that emits this for
every case, and regenerated all 11 fixtures again with it. Re-verified: the
`[coef]`/`[vcov]`/`[fit]`/`[tol]` content is unchanged from the no-`[se]` pass
above (see "Result" section); only the new `[se]` block was added.

`gen_fixtures.R` was touched only for this addition — no other lines changed.
