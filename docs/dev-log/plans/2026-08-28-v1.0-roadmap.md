# The v1.0 roadmap — from a completed ledger to a stable twin

**Written 2026-08-28 (Fable, D-151), the morning after v0.2.0.** Issue #9's one line — *"Full twin —
every drmTMB capability matched, speed edge documented per family"* — was written when both halves
were distant. The speed table is landed (`report/speed-per-family.md`) and the admitted ledger is
complete, so #9 needs re-founding, not execution. Two facts do the re-founding:

1. **The twin moves.** drmTMB merged seven family-specific `mi()` missing-data capabilities in the
   last two weeks (two independent Gaussian terms #1086; Gamma #1088; LogNormal #1092;
   BetaBinomial #1094; NB2 #1095; Student #1096; ZIP #1097 — the codex lane's active axis, still
   going). None is in the capability ledger, and DRM.jl's counterpart (#49 FIML) is deliberately
   PARKED (#453). "Every capability matched" against a moving target is a receding finish line.
2. **v1.0 means API stability.** In Julia's SemVer culture a 1.0 is a promise that the public
   surface — `bf()`, `drm()`, the family constructors, the accessors — stops breaking. That
   promise, not a feature count, is what the tag certifies.

## Destination

> **DRM.jl is v1.0 when: the twin claim holds against a PINNED drmTMB reference with the mi() axis
> resolved by decision (matched, or fenced as a named delta); the public API is surveyed, frozen,
> and deprecation-clean; the bridge has zero known bugs; the interval-trust question has its
> deliberate post-tag answer (D-179 #4's "revisit"); and the registration question is decided —
> not necessarily YES, but decided. Tag `v1.0.0` certifies the promise.**

The pin rule: at arc start, freeze `drmTMB@<ref>` as the v1.0 comparison baseline. Later drmTMB
movement is a tracked delta with its own ledger note — never a silent widening of the finish line.

## The waves

### Wave M — the mi() question *(the fork in the road — DECISION #1)*

The only item that changes the arc's size by an order of magnitude.

- **Fence** *(sessions: ~0.2)* — a ledger delta-note naming the seven mi() capabilities as
  post-pin drmTMB movement, excluded from the v1.0 twin claim, tracked for a future arc. Honest,
  cheap, and consistent with #49's deliberate PARKED status.
- **Match** *(sessions: ~10–20, campaign-shaped)* — unpark #49 and build observed-data likelihoods
  per family. Real engine work with derivations; it would dominate the arc and re-open every time
  the codex lane ships another family.
- *Recommendation: fence for v1.0; schedule the match as the headline of the post-1.0 arc once
  drmTMB's mi() axis itself stabilises. Matching a moving axis mid-flight buys permanent chase.*

### Wave Q — quality debt to zero *(~2 sessions)*

- **drmTMB#1090** — the live Workflow G robust-student cell errors in DRM.jl's `_bridge_formula`
  (univariate Student read as bivariate). The one known bridge bug; needs the verify-first
  treatment. Blocks the "zero known bridge bugs" limb.
- **#526** — q4 REML `converged` semantics (decision + small patch).
- **#527** — the audit's ladder-hardening lows.
- **Close #482** — its two halves (drop, include) both landed in the completion arc; the issue
  outlived its fix.
- **#8** — close: its gate was met and superseded by v0.2.0 (D-179 #6, D-111 carve-out recorded).

### Wave I — the interval answer *(DECISION #2; 0 or campaign-sized)*

D-179 #4 said "Option 1 now; revisit after the tag." The tag exists, so the revisit is due — once,
deliberately, then closed:

- **Permanent-permanent** *(sessions: 0)* — the fences stay documented boundaries forever; #495
  remains a recorded finding. v1.0's docs say "capability parity, not coverage" in one visible
  place.
- **Earn `coverage_claimed`** *(campaign-shaped; Totoro pilots + DRAC arrays, D-139-estimated)* —
  the #495 profile-vs-Wald discriminating experiment first (per-coefficient `parm` is ready), then
  targeted campaigns only where the measured splits say nominal is reachable.
- *Recommendation: permanent-permanent for v1.0. The completion arc's own doctrine — usability
  uncompromising, accuracy contextualised — cuts against spending campaign-weeks on a claim the
  package's users have not asked for.*

### Wave A — the API freeze *(~2–3 sessions)*

- Survey every export against drmTMB's naming contract (`sigma` never `tau`, `rho12`, `meta_V`);
  deprecate-or-commit each; write the stability note in the docs.
- **#471** — structured markers, STUDENT only (the LogNormal half is already implemented and
  tested via log-delegation): in or out of the frozen surface *(DECISION #3; drmTMB's own
  `biv_student()` defers structured effects, so "out, documented" matches the twin)*.
- **#136 VA/ELBO** stays Experimental-labelled in 1.0 (already carved out on the Documenter site);
  Experimental surfaces are exempt from the stability promise, stated explicitly.
- Docs completeness pass over the 26 Documenter slugs; the two named carve-outs keep their labels.

### Wave R — the release *(~1 session + owner ceremony)*

- **Registration** *(DECISION #4)* — a Julia 1.0 usually registers in General; D-111 currently says
  OFF. Decide: register at v1.0, or tag without registering and record the carve-out again. *(No
  recommendation — this is ecosystem-strategy, owner's territory; note only that an unregistered
  1.0 is unusual but coherent with the GitHub/`Pkg.develop` distribution D-111 chose.)*
- Re-run the benchmark table at the pinned ref; CHANGELOG; `Project.toml` → 1.0.0; tag.
- drmTMB's D-164 CRAN hold is untouched by all of this.
